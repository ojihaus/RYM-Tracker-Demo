- 차트 형식 검사와 파일명 규칙을 서버와 브라우저가 공유합니다. RYM URL, UTC 날짜, 정수 순위, 곡·순위 중복, 2MB 크기 제한을 검증합니다. 잘못된 행을 조용히 버린 뒤 불완전한 차트를 저장하지 않습니다.

- 목록은 매번 GitHub의 현재 디렉터리를 확인합니다. 메타데이터는 불변 Git blob SHA를 키로 캐시하고, 처음 읽을 때는 병렬 요청을 4개로 제한합니다. 선택한 차트의 실제 곡만 브라우저로 전송합니다. 일부 파일 오류는 사용자에게 명시합니다.
- 삭제 중 갱신된 파일은 SHA 충돌로 보호합니다. 이미 삭제된 파일을 다시 삭제해도 성공으로 처리합니다. 브라우저에서는 성공한 삭제부터 반영하고, 부분 실패를 구분하며, 선택한 차트가 사라지면 유효한 차트로 복구합니다.
- 업로드 성공 후 목록 갱신만 실패한 경우 업로드 실패로 잘못 안내하지 않습니다. 작업 중 버튼을 잠그고 동기식 재진입 방지로 중복 제출을 막습니다. 알림창 대신 화면 내 진행·완료·오류 메시지를 사용합니다.
- 기존 요청이 늦게 도착해 삭제된 항목을 복원하거나 다른 버전의 내용을 덮어쓰지 않도록 취소·세대 번호·SHA 확인을 적용했습니다. 같은 기록의 동시 조회도 합칩니다.

- 기존 30:70 구성, 밝은 색상, 상승·하락·신규 강조, 한영 전환, 주차별 비교와 새 방문 시 최신 2020s 기록 선택을 유지했습니다. 서브차트는 PC에서 열리고 1023px 이하에서는 닫힌 상태로 시작합니다.

## 확인할 운영상 제한

- **기존 PIN을 한 번 변경해 주세요.** 현재 공개 저장소에 있는 구형 v2 해시는 4자리 PIN을 오프라인으로 대입해 볼 수 있는 형식입니다. 이번 변경은 기존 로그인을 유지하고, 다음 PIN 변경부터 서버 비밀값으로 보호된 v3 해시를 저장합니다. 과거 Git 기록은 지워지지 않으므로 종전 PIN을 계속 쓰면 이 문제는 해소되지 않습니다.
- `ADMIN_PIN_PEPPER`를 설정하지 않고 v3 PIN을 만든 경우 GitHub 토큰이 보호 키로 사용됩니다. 그 뒤 토큰을 교체하면 PIN도 재설정해야 합니다. 장기 운영 시 고정된 `ADMIN_PIN_PEPPER`와 `ADMIN_SESSION_SECRET`을 배포 환경에 별도로 설정해 두시는 편이 좋습니다. 기존 v2 PIN 읽기에는 새 환경변수가 필요하지 않습니다.
- 로그인 시도 제한은 서버 인스턴스별 메모리 제한입니다. Vercel처럼 인스턴스가 늘어나는 환경의 공통 제한은 플랫폼 방화벽 또는 공용 저장소를 이용한 추가 구성이 필요합니다. 4자리 PIN 자체가 강력한 관리자 인증을 제공하는 것은 아닙니다.
- GitHub Contents 디렉터리 목록은 파일 수가 매우 많아지면 별도 인덱스/저장소로 옮겨야 합니다. 메타데이터 캐시도 서버 인스턴스별이며 재시작 후 다시 생성됩니다.
- 저장소·세션 동작은 테스트 응답으로 검증했습니다. 실제 배포 환경의 토큰 권한과 비밀값, Vercel 환경변수는 이 작업에서 조회·변경하지 않았습니다.
- 브라우저 검증에서는 Spotify 응답을 모의했습니다. 실제 음원 재생은 Spotify의 지역·로그인 상태·브라우저 자동재생 정책에 따라 달라지며 iframe 내부에서 한 번 더 재생을 눌러야 할 수 있습니다.
